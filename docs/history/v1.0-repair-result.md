## Why the original repair result was withdrawn

The first repair-agent report claimed `72/72 PASS` and `47 passed (27 helper + 20 contract)` while the PR's GitHub Actions run was red. Hostile review found that:

1. CI's production-Sheet-ID guard was contradicted by tests containing the same literal.
2. `pyproject.toml` restricted pytest discovery to `tests/`, so the root `test_helpers.py` suite was not proven by the claimed pytest count.
3. several MCP qualification cases tested Pydantic output models rather than actual MCP tool calls.
4. structured crawl/sync counts were inferred from human stdout patterns that did not match the scraper's real output.
5. `crawl_jobs` was incorrectly annotated as MCP `readOnlyHint=true` even though it writes local crawl/cache/seen artifacts.
6. Skill validation was home-grown rather than performed by the authoritative `skills-ref` reference validator.
7. there was no tooling-generated reproducible dependency lock.

Those claims are no longer treated as evidence.

## Primary correction completed

### MCP behavioral contract

- `crawl_jobs` remains unable to write Google Sheets, but its MCP annotation now truthfully declares that it can mutate local artifacts:
  - `readOnlyHint=false`
  - `destructiveHint=false`
  - `idempotentHint=false`
  - `openWorldHint=true`
- invalid `source` and `range` are tested through an actual MCP `Client` call and must be rejected before `_run_subprocess` executes.
- representative `crawl_jobs` is tested through MCP without any Sheet configuration.
- representative `sync_jobs_to_sheet` is tested through MCP with synthetic Sheet ID/GID/credential fixtures and exact target propagation.
- a real STDIO client now spawns `server.py`, initializes the protocol, lists all four tools, and calls the fail-closed `audit_sheet` path.

### Stable machine-readable result contract

`sg_product_jobs.py` now supports the internal `--json-summary` switch and emits one final line prefixed with:

```text
JOBS_SCRAPER_SUMMARY=
```

The MCP layer parses only this JSON contract for:

- `jobs_found`
- `jobs_enriched`
- `jobs_failed`
- `output_file`
- `written`
- `skipped_dup`
- `skipped_no_jd`

If a subprocess exits successfully but the summary contract is missing or malformed, the MCP tool fails closed with `OUTPUT_CONTRACT_MISSING` instead of inventing counts from prose logs.

### Google Sheet safety

- author Sheet ID/GID fallback remains removed.
- `.env.example` now leaves `SHEET_ID` actually empty rather than using a non-empty placeholder.
- placeholder Sheet IDs are rejected as `CONFIG_MISSING`.
- external scraped values remain `RAW`.
- intentional E-column `HYPERLINK` formulas remain `USER_ENTERED`.
- data columns are written before the E-column formula, so an injected data-phase failure cannot activate the live formula first.
- fault-injection coverage verifies the formula phase is not reached when an earlier data phase fails.
- CI contains no production Google credentials and does not perform production writes.

### Packaging and reproducibility

- `skills/jobs-scraper/SKILL.md` is validated in CI with the authoritative `skills-ref` implementation pinned to agentskills commit `69ef37e9424c0a7ea9dd2293b559e43ec8176379`.
- `uv.lock` is tooling-generated and checked with `uv lock --check`.
- CI installs with `uv sync --locked --extra dev --python 3.11`.
- stale `scrapling[parser]` was replaced with supported `scrapling>=0.4.14,<0.5`; the prior 0.4.14 warning about a nonexistent `parser` extra is eliminated.
- the one-shot primary repair patcher was removed after applying the bounded correction.
