# v1.5 — Modular refactor (stage 2 of the unification)

## Where this comes from

The 2026-10-26 unification ended the split between the plugin runtime and this
repository: one version line, one build, three identical copies. That release
(`v1.4.0`) deliberately kept the existing shape — `sg_product_jobs.py` is a
single ~3400-line module that owns source crawling, the title skip filter, JD
extraction, dedup, and Sheet row writes for all five sources.

This document is the plan for the stage-2 refactor: splitting the *fetching*
half of that module out into per-source adapters, the way upstream v1.3.x did
for LinkedIn before the sources were retired.

**Nothing in v1.4.0 depends on this.** The refactor is a structure change, not
a behaviour change. If it is not started, nothing breaks.

## Goal

Move URL building, list parsing, and JD fetching out of `sg_product_jobs.py`
into `jobs_scraper/sources/<source>.py`, leaving the module to own orchestration
and business rules (skip filter, dedup, Sheet write, CLI).

```
jobs_scraper/sources/
  linkedin.py        # build_list_url, parse_list_page, fetch_list_page, fetch_jd
  jobstreet.py       # build_*_list_url, parse_*_list_page, fetch_jobstreet_jd
  onezerofour.py     # 104: build_*, parse_*, fetch_*
  cake.py            # build_*, parse_*, fetch_cake_jd
```

The upstream v1.3.1 `jobs_scraper/sources/linkedin.py` is the reference
implementation for the shape: a session is injected by the caller, the adapter
owns no global state, and `sg_product_jobs.py` keeps compatibility wrappers for
the existing public surface.

## What must not change

These are frozen contracts. The refactor is verified by them, not by review.

- **Title filter v8.5.** `match_skip_reason` and the eight filter layers. This
  is a separately qualified contract with 414 lock-in tests; the refactor must
  not touch it. `SKIP.md` §18 records where the document and the runtime
  already disagree — do not widen that list.
- **Sheet write order.** `A:D RAW` → `F:K RAW` → `E USER_ENTERED`. The
  E-column HYPERLINK is written last on purpose.
- **Cross-source identity.** `(source, job_id)`.
- **Work-mode values.** `Remote | Hybrid | Onsite | Unknown`.
- **Retry ladders.** LinkedIn list page 30/60/90s × 4 attempts; the same shape
  for Cake and 104.
- **`seen_jds.jsonl` as a single source of truth.** The refactor must not
  introduce a second copy or a second location.
- **Source routing.** LinkedIn/JobStreet → `SG-Raw`; 104/Cake → `TW-Raw`; Jora
  retired but still back-compat readable.

## Method

1. Move one source at a time, starting with 104 (smallest surface, one slug
   grammar) and ending with LinkedIn (largest, and the one with the most
   production history).
2. For each source: extract the functions, keep the old names as wrappers in
   `sg_product_jobs.py`, and let the existing 770-test suite prove nothing
   changed. The suite must stay green at every commit.
3. Add a per-source contract test file for each new adapter, in the shape of
   the existing `tests/test_onezerofour_*.py` and `tests/test_cake_*.py` files.
4. Update `scripts/check_equivalence_freeze.py` and the golden file to the new
   layout, the way v1.4.0 updated them for the five-source contract.
5. Keep `SKIP.md`, `RULES.md`, and `CHANGELOG.md` in step with the change.
